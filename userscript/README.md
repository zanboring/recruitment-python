# 油猴脚本采集通道

在**你自己真实登录态的浏览器**里采集招聘岗位，回传给本地 RecSys 服务。

## 为什么要有这条通道

| | 服务端爬虫（`app/crawlers/`） | 油猴脚本（本目录） |
|---|---|---|
| 运行环境 | 无头 chromium | 你的真实浏览器 |
| 登录态 | 无（抓公开列表页） | **你的真实登录态** |
| 网络指纹 | 有自动化特征 | 与真人浏览完全一致 |
| 访问来源 | **集中 IP** | 你的日常 IP，无集中特征 |
| 被封风险 | 需要代理池、限速、配额来压 | **不存在触发条件** |
| 适合 | 批量历史采集、定时全量 | 按需采集、登录后可见的数据 |

一句话：**服务端爬虫是在跟反爬对抗，油猴脚本是绕开了对抗的前提。**

## 安装（3 步）

1. 你已装好 **篡改猴（Tampermonkey）** ✅
2. 打开篡改猴面板 → 「添加新脚本」，把 `recsys-collector.user.js` 的内容整段粘进去 → 保存
   （或在浏览器里直接打开这个 `.js` 文件，篡改猴会弹出安装页）
3. 打开任意招聘页面（BOSS 直聘 / 前程无忧），右下角会出现 **RecSys 采集器** 面板

## 服务端准备（必需，否则接口是关闭状态）

采集入口**默认关闭** —— 没配令牌时接口直接返回 403。这是刻意的默认安全。

```bash
# 1. 生成一个令牌
python -c "import secrets;print(secrets.token_urlsafe(24))"

# 2. 写进 .env（或 config.env）
BROWSER_COLLECT_TOKEN=你刚生成的那串

# 3. 重启服务
```

然后在浏览器面板点 **「设置」**，把服务地址（默认 `http://localhost:8080`）
和同一串令牌填进去。

## 用法

| 按钮 | 作用 |
|---|---|
| **预览** | 只识别不发送，显示「定位到多少条 + 前 5 条原文」。**选择器改版时先点这个** |
| **采集当前页** | 识别当前页并回传，返回「新增 / 重复 / 被过滤 / 无效」四项计数 |
| **自动翻页采集** | 按你指定的页数自动翻页，每页之间**随机等待 3~8 秒**（跟着人的节奏走） |
| **设置** | 改服务地址与令牌 |

采集结果在「数据管理」页按平常一样查看即可 —— 它走的是**同一条入库链路**，
和爬虫采到的数据没有区别。

## 原理：为什么「用前端代码爬取」只能靠扩展

纯页面 JS（控制台 / 书签脚本）**做不到**，这是浏览器的硬性设计：

- 从 `zhipin.com` 的页面里 `fetch('http://localhost:8080/...')` 会被 **CORS** 拦掉
  —— 对方不会返回 `Access-Control-Allow-Origin`；
- `mode: 'no-cors'` 虽然能发出去，但拿到的是 **opaque 响应，读不到任何内容**；
- 带自定义请求头的请求还会先触发**预检（preflight）**，同样被拒；
- JSONP 现代站点早已不提供。

而油猴的 **`GM_xmlhttpRequest` 是特权 API，不受同源策略限制** —— 这就是这条路的
全部依据。（`@connect localhost` 是声明允许访问的目标，缺了会被篡改猴拦住。）

### 一个顺带得到的安全设计

回传使用自定义头 `X-Collect-Token`。自定义头会触发跨源预检，而**普通网页拿不到预检许可，
根本发不出这个请求**；油猴脚本不受此限。等于借浏览器自己的同源策略，
顺手挡掉了「任意网站偷偷往 `localhost:8080` 灌数据」。

即使如此，服务端仍然校验令牌（用 `hmac.compare_digest` 做定时安全比较），
并且**没配令牌就整条入口关闭** —— 默认安全，不留「能写但没鉴权」的窗口。

## 设计原则：脚本只做「哑采集器」

浏览器端**只从 DOM 取原始文本**，不做任何业务判断：

| 交给浏览器 | 留在服务端（`crawler_service.ingest_browser_jobs`） |
|---|---|
| 取标题 / 公司 / 城市 / 薪资 / 标签的**原始文本** | `job_key` 指纹生成 |
| | 薪资解析（`1-1.5万` / `8K-12K` …） |
| | 技能关键词抽取 |
| | 三道过滤（高级岗位 / 无效岗位 / 薪资异常） |

**为什么这样分**：如果脚本自己算 `job_key`，两个采集入口（爬虫 / 浏览器）的
口径就会漂移 —— 同一个岗位在库里出现两行，统计翻倍。
所以服务端强制用同一个平台标识（`boss` / `51job`），并**不接受**脚本传来的指纹。

### 另一个刻意的差异：浏览器采集不触发「下架判定」

爬虫是按「关键词 × 城市」**系统性抓取**、覆盖范围已知，所以它可以判断
「哪些岗位没再出现 → 标记下架」。

而浏览器采集是「用户浏览到哪就采到哪」的**部分数据**。拿它去判断下架，
会把库里所有没被这次浏览覆盖到的岗位整批误判下架。所以这条通道**只做新增/刷新，不做下架**。

## 站点改版了怎么办

招聘网站的类名会改。脚本按三层应对：

1. **多候选选择器**：每个字段都给多个候选按顺序试（`SITES` 里的 `card` / `fields` / `tags`）；
2. **兜底定位**：类名全失效时，改为「按指向岗位详情页的链接」定位卡片，
   再向上找到文本量合适的容器 —— 类名会变，但「岗位标题是个指向详情页的链接」
   这个结构很少变；
3. **预览模式**：点「预览」会告诉你**本次是用哪个方式定位到的**（选择器名字 or 兜底），
   一眼就能看出是不是失效了。

要加新站点，只需在 `SITES` 数组里加一个适配器对象（平台标识 + 选择器表），
不用动其它逻辑。

## 已知限制（如实记录）

- **选择器未在真实站点验证过**。开发环境无法访问外网，所以 `SITES` 里的选择器
  是按站点公开结构写的**有依据的猜测**，首次使用请先点「预览」确认。
  失效时按上节的三层机制修，通常只改 `SITES` 表即可。
- **自动翻页依赖「下一页」按钮能被识别**（脚本会找 `a[href*="page="]`、
  `.next`、或文本含「下一页」的元素）。识别不到会停在第 1 页并提示。
- **单次提交上限**默认 500 条（`BROWSER_COLLECT_MAX_BATCH`），
  防脚本写错一次灌进几万条。
- 采集走的是**用户真实 IP**，所以不受服务端日配额限制 —— 但这也意味着
  **频繁自动翻页的后果由你自己的账号承担**，建议把间隔留在默认的 3~8 秒以上。
